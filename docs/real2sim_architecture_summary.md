# Real2Sim Pipeline：阶段与验收

依据：[整体架构设计](../../REAL2SIM_ARCHITECTURE.md)。包含已实现与规划阶段；“已有实现”不代表所有案例已通过验收。每个阶段包含简介和 Eval；Eval 统一描述验收标准、验证方式与证据。

整体流程：**观测 → 示范理解 → 场景重建 → 外观优化 / 机器人轨迹生成 → 数据生成 → 多后端导出**。机器人接入可独立进行，各阶段也可从已有产物开始。Scene IR 是统一数据源，MuJoCo、Blender、USD 从它生成。

## S0 · 机器人接入（已有实现）

**介绍：** 将 URDF、视觉资产和可选机器人日志/图像整理为 RobotBundle，统一关节、末端、执行器、碰撞和相机定义，供后续运动生成使用。

**Eval：** 模型可加载；运动学与关节约定正确；手/工具安装、视觉与碰撞合理；执行器限位和参数有来源。证据不足的检查标记 `not_run`，不能默认为通过。 验证时，Bundle 校验与 MuJoCo 编译；使用 `robot_log_check` 比较 FK 和末端日志；使用 `robot_overlay` 在未参与拟合的帧上检查姿态、安装和外观；检查静止自碰撞。

现有标准：[robot.yaml](../rubrics/robot.yaml)。

## S1 · 示范理解（部分实现，独立阶段规划中）

**介绍：** 对齐视频、标定和轨迹的时间与坐标，识别对象及接近、抓取、搬运、释放等事件，输出 ObservationBundle 和 TaskBundle。当前已有输入登记和手轨迹导入，独立 TaskBundle 与完整自动理解流程尚待实现。

**Eval：** 时间和坐标一致；跨帧对象身份正确；任务事件有观测依据；成功/失败条件与允许的动作调整明确；未知信息和尺度不确定性显式记录。 验证时，检查时间戳、坐标变换和多视角同步；将轨迹/关键点重投影到原视频；在关键事件帧上核对对象、接触和任务语义；审查输入来源及 withheld 约束。独立 rubric 待实现。

## S2 · 场景重建（已有实现，通用能力持续扩展）

**介绍：** 从分割、相机、深度和尺度估计出发，重建背景与交互物体，拟合几何、静止位姿和碰撞体，写入 Scene IR。生成式 3D 提供初稿，agent 可通过参数化建模和渲染拟合修正结构。

**Eval：** 相机和尺度有交叉验证；物体轮廓、开孔、把手等结构符合观测；隐藏部分有来源标记；支撑、容器内部和碰撞有效；静置稳定且穿透在阈值内。 验证时，`scene_ir.validate`；`geometry_metrics` 测量各静止状态不同帧上的 IoU、边界和内部边缘；查看 `render_views` 叠图与结构近景；用独立尺度线索交叉检查；运行 `mujoco_check` 检查穿透、沉降和容器空腔。

现有标准：[scene.yaml](../rubrics/scene.yaml) 的几何、尺度与物理项。

## S3 · 外观优化（已有实现）

**介绍：** 在稳定几何上恢复干净材质、纹理和统一灯光，输出可编辑 Blender 场景。观测纹理需要去光照与去干扰，未观测区域使用合理补全。

**Eval：** 无手、设备、烘焙阴影、接缝或拉伸残留；材质与真实场景一致；阴影由灯光产生；固定评估协议下分区域外观指标达标；保存的场景可重新打开并复现。 验证时，用 `blender_render` 检查源视角、纯背景、新视角和物体转台；检查纹理原图，结合 `sam3_segment` 排查残留；用 `image_metrics` 报告 SSIM、LPIPS、PSNR；重新打开 `.blend` 渲染验证。规划进一步统一 held-out 评估协议及 ScenePatch 回写。

现有标准：[scene.yaml](../rubrics/scene.yaml) 的清洁度、材质、灯光与外观项。

## S4 · 机器人轨迹生成（已有实现，稳健性验证待扩展）

**介绍：** 将示范轨迹配准到场景，经机器人摆放、手部重定向和机械臂 IK 得到控制目标，再通过 MuJoCo 执行与抓取修正完成任务。分别保存 `reference`、`commanded` 和 `achieved`，最终渲染使用实际执行结果。

**Eval：** 配准、尺度和机器人摆放合理；关节、执行器和碰撞满足限制；物体通过真实接触完成任务并稳定释放；动作忠实度单独达标。不能使用瞬移、临时焊接或隐式外力伪造成功。 验证时，在未参与拟合的帧上检查手轨迹重投影；独立重跑 `mujoco_rollout`，对照 achieved 状态并检查接触、穿透、限位、饱和和跟踪误差；用 `video_compare` 检查物体终态、手/物体路径及事件时间；查看完整对比视频。规划增加初始误差和物理参数扰动下的成功率测试。

现有标准：[trajectory.yaml](../rubrics/trajectory.yaml)。必须区分运动学回放、原生动力学执行和扰动下的稳健执行；任务等价的动作调整也需与忠实复现区分。

## S5 · 数据生成（规划）

**介绍：** 基于场景、任务、机器人和可执行动作来源，随机化外观、观测、布局、动力学或目标，经再规划、执行、过滤和批量渲染生成 DatasetBundle。

**Eval：** 随机化满足支撑、间隙和可达性约束；每个涉及物理变化的 episode 独立通过任务与物理验收；动作/状态/图像标签同步且语义明确；种子和接受/拒绝统计可追溯；数据划分不存在同源示范或资产族泄漏。 验证时，先运行低成本 rollout 并逐条验收，再高质量渲染；审计参数分布、拒绝原因、控制/渲染时间戳与标注；检查 train/val/test 的家族归属。纯外观变体只有在物理哈希一致时才能复用执行证据。独立 rubric 与数据流水线待实现。

## S6 · 多后端导出（部分实现）

**介绍：** 将同一版本的 Scene IR、RobotBundle 和 MotionBundle 编译为 MuJoCo、Blender 和 Isaac 发布包，保留实体、关节、材质及动画映射。

**Eval：** 依赖完整、单位和坐标一致、映射正确、目标环境可加载；明确声明 `loadable`、`kinematic_playback` 或 `native_execution` 能力级别。跨引擎物理执行必须分别验收。 验证时，在干净进程中加载并检查资源、关节、碰撞和材质；对照回放状态与源 motion；若声称 Isaac 原生可执行，必须在 Isaac 中重新运行控制并检查任务/接触指标。

当前已有 MJCF、Blender 和 USD 导出；`export_usd` 做 USD 结构检查并生成 playback，尚未验证 Isaac 本身的加载与原生执行。完整独立导出 rubric 和目标引擎验收待实现。

## 统一 Eval 闭环

**构建与自检 → 冻结候选 → 独立 evaluator 验证 → 逐项报告 → 按根因修正 → 重新验收。**

- 固定候选、父产物和 rubric 的版本/哈希；evaluator 不修改候选，重新测量关键结果。
- 报告每项标准的状态、指标、证据和失败负责阶段；所有 hard gate 通过才能接受，未知项不能默认为通过。
- 父产物变化后重验受影响的证据：纹理变化主要影响视觉，尺度/碰撞/质量变化影响动力学。完整字段级自动失效机制仍在规划中。
- 预算耗尽时保留最佳候选与未通过项，不将未通过结果标为成功。

当前评估入口：[evaluate-robot](../skills/evaluate-robot/SKILL.md)、[evaluate-scene](../skills/evaluate-scene/SKILL.md)、[evaluate-trajectory](../skills/evaluate-trajectory/SKILL.md)。
