# any2sim — 重建与数据生成流水线

## 1. 概述

any2sim 通过三个串联步骤，将示范视频转换为机器人训练数据集：

1. **重建：** 将场景重建为可用于仿真、具有照片级真实感的数字孪生。
2. **轨迹生成：** 将人类示范转换为在该数字孪生中通过物理仿真执行的机器人运动。
3. **数据生成：** 将这一次实际执行的任务扩展为多个随机化、经过物理验证并完成渲染的任务序列，按机器人的数据格式输出。

机器人接入独立进行，为第 2、3 步提供经过验证的机器人模型。

每一步都从上一步**已冻结、通过哈希固定版本**的结果开始。后续步骤若要修改前序结果，必须声明修订，并提供证据支持。

## 2. 场景重建

**目标：** 构建一份场景描述，使相机、真实尺度、世界坐标系、静态结构及所有交互物体与真实场景一致。物体不仅要轮廓相似，其形状和结构也必须匹配。场景还必须具备可靠的碰撞几何、干净的材质，以及能够产生真实阴影的灯光。

### 2.1 几何与物理

工作遵循固定的依赖顺序：先确定相机与尺度，再构建几何、验证接触，最后优化外观。

| 步骤 | 工作内容 | 验证方式 |
|---|---|---|
| **1. 观察** | 登记视频并选择关键帧。记录静态结构、交互物体、动态干扰物（手、工具、线缆）、相机运动，以及难点（薄结构、开孔、遮挡） | 人工查看总览图 |
| **2. 分割与跟踪** | 根据文本提示生成实例掩码，并在视频中传播，保持身份一致。显式标记干扰物（手、手套、手臂、追踪器、线缆） | 干扰物掩码不得错误覆盖目标物体 |
| **3. 相机估计** | 使用学习式多视图模型估计多帧相机位姿和内参，并与单图米制深度、特征匹配及平面拟合交叉核验 | 两种独立方法必须一致 |
| **4. 真实尺度** | 比较至少两种独立尺度线索，包括多帧观测、物体尺寸先验、已知尺寸物品。记录舍弃某条线索的原因，并说明不确定性 | 整体等比缩放不会改变像素投影，因此不能通过图像指标“确认”尺度 |
| **5. 世界坐标系** | 对主要支撑面拟合平面，令重力沿 −z 方向 | — |
| **6. 物体形状：初稿、检查与重建** | 图像生成 3D 模型给出相机坐标系中的初稿，与多帧局部特写比较。若比例或结构（开孔、槽、边沿、把手、盖子）不正确，Agent 编写**参数化形状生成器**，通过渲染对比拟合形状参数与位姿，使用掩码、内部边缘和深度作为依据。对于不规则自然形状，则使用自由顶点偏移 | 在每个静止状态的**所有**帧上检查轮廓 IoU、轮廓误差、内部边缘对齐，并进行目视检查 |
| **7. 静止状态** | 找出各物体静止且未被触碰的时间段。每个状态拟合一个位姿，各状态共享形状。支撑面上的静置物体按平面位姿处理，即 x、y 和偏航角 | 使用不同且非重复的留出帧验证 |
| **8. 补全标记** | 对隐藏部分进行合理补全，并标为 *completed*；生成部分标为 *generated* | 转台展示中没有明显错误的补全 |
| **9. 碰撞与物理** | 进行凸分解，容器需足够精细以保留内部空腔，再仿真检查沉降和穿透。修复几何、支撑或位姿等根因 | 穿透和漂移符合阈值，容器保留有效空腔 |

### 2.2 外观

| 步骤 | 工作内容 |
|---|---|
| **逐表面选择材质** | 每个表面采用三种处理之一：*观测纹理*，仅在掩码处理后确认干净时使用；从已验证干净的局部区域生成的*样例合成纹理*，作为桌面、地板和墙面的默认方案；或*程序化纹理／恒定颜色*。未经证明干净的原始视频像素不能直接作为交付纹理 |
| **去光照** | 反照率 ≈ 观测到的线性辐亮度 ÷ 烘焙辐照度。烘焙时使用对应帧中的几何，并采用统一的全局光照尺度，使反照率保持合理 |
| **灯光配置** | 整段视频使用同一套灯光。根据真实投影阴影的偏移估计主光方向，根据阴影柔和程度估计光源尺寸，根据阴影区域估计环境光强度。对足够范围的房间建模，以解释间接光和遮挡。未观测到的光源位置标为先验 |
| **表面细节** | 磨损应有明确位置和成因，如经常触碰的区域、工具路径或边缘。起伏按真实物理尺度处理：影响轮廓的褶皱使用几何，细微纹理使用法线和粗糙度细节。避免重复感明显的程序化图案 |
| **曝光与照明分离** | 在代表性帧上分别拟合曝光和照明。逐帧相机响应只能依据各帧共有的静态像素估计，并单独报告 |
| **验证** | 源视角对比，包括静态区域的结构相似度和物体的感知距离；纯背景渲染，检查原手部或物体位置的残影；新视角，检查悬浮或拉伸；转台展示，检查隐藏面和接缝；直接查看纹理图像 |

**输出：** 场景描述，以及由其编译得到的物理场景和可编辑的照片级真实感渲染场景。

## 3. 机器人接入（支撑步骤）

将任意机器人形态整理为**经过验证的机器人包（RobotBundle）**：

1. 导入机器人描述，为各连杆添加逼真的视觉模型和碰撞体。
2. 对照日志中的末端执行器位姿、关节范围和速度，检查正向运动学。
3. 根据图像和关节日志拟合机器人搭载相机的位姿，并按日志关节状态渲染机器人，与真实帧叠加比较。
4. 可选：根据真实观测拟合线缆和各部件材质。
5. 通过独立评估后，发布机器人包。

下游步骤通过哈希引用机器人包，且不得修改。仅涉及外观的修订保持旧场景有效。

## 4. 轨迹生成：从示范到机器人实际执行

**输入：** 冻结场景、视频、跟踪掩码、米制手部轨迹（手腕位姿、关键点，以及可选的重定向手指关节），以及经过验证的机器人包。

1. **理解任务序列。** 从**轨迹**中识别接近、抓取、搬运和释放，包括抓取停留、搬运和释放事件，而非根据视频帧猜测。记录开头静止的控制渐入帧。
2. **配准轨迹。** 手部轨迹具有米制尺度，作为**尺度参考**：只允许旋转和平移，**绝不缩放**。比较多种线索，包括手部搬运距离与物体位移、抓握开度与物体宽度，以及接触约束下的配准。如果这些线索一致表明场景尺度错误，则声明修订并对场景整体等比缩放，要求源视角投影不变，然后重新进行轨迹刚性配准。在未参与拟合的帧上检查重投影。
3. **摆放机器人基座。** 整段参考运动必须处于可达范围内并留有余量，安装方式符合机器人实际条件，且初始位姿不得与桌面接触。
4. **手部重定向。** 将人类关键点转换为掌心位姿和机器人手指关节，并报告每个关键点的残差。由于机器人与人类的手指结构不同，抓取附近优先考虑与接触相关的点，如指尖。
5. **求解机械臂逆运动学（IK）。** 根据掌心目标求解关节，并检查关节限位、平滑性、速度、肘部翻转及与桌面的接触。
6. **将参考运动转换为控制指令。** 将掌心与手指的运动学参考转换为所有受驱动关节的逐帧目标。
7. **进行物理修正。** 运动学参考通常会穿入或错过物体。通过完整任务序列的仿真，优化少量可解释参数：接近间隙、接触后继续闭合手指以产生抓握力、掌心相对物体的位姿、搬运前先抬起，以及释放时机。评分综合考虑物体最终位姿、不掉落、穿透、限位、执行器饱和、相对参考运动的偏差和事件时间。
8. **执行。** 最终控制指令通过机器人执行器在仿真器中运行。记录实际运动，并进行确定性检查和模型审计。
9. **渲染与比较。** 从源相机视角对**实际运动**进行照片级真实感渲染，使用根据源视频拟合的相机成像模型。将渲染结果与真实视频并排比较：机器人手是否位于原人手位置、手部尺度是否正确、物体是否沿示范运动、静态区域是否保持一致，以及接触时间是否匹配轨迹事件。
10. **导出。** 输出物理场景、渲染场景，以及带运动回放层的 Isaac 场景。

**始终区分三种运动：**

| 运动 | 含义 |
|---|---|
| reference | 从示范推导出的运动学目标 |
| commanded | 实际执行的执行器目标 |
| achieved | 物理仿真实际产生的运动；用于渲染和评分的唯一运动 |

**真实物理约束：** 机器人只能通过执行器运动，物体只能通过接触运动。不得使用焊接约束、附着、瞬移、mocap 或不可见外力，也不得在缺乏证据的情况下修改物体物理参数。

## 5. 数据生成：从一次任务执行到数据集

**输入：** 包含已执行任务序列的冻结米制场景、经过验证的机器人包（头部和腕部相机、执行器、数据映射），以及目标数据集格式。

### 5.1 步骤

1. **理解示范。** 确定执行动作的手、接触／抬起／放置／释放帧、机械臂与关节限位的距离，以及抓取的稳健程度。这些决定任务序列可以变化的幅度。
2. **定义任务成功判定条件。** 例如：*物体已释放并静止在容器内，容器保持直立*。该条件必须在标称（未随机化）执行中通过，在明显失败的案例中不通过。
3. **根据证据设置随机化范围。** 每次只调整一个维度，从小范围开始，在接受率保持合理的前提下逐步扩大。每个范围都在工作日志中说明依据。
4. **小批量试运行。** 运行少量任务序列，查看按阶段和原因分类的拒绝统计，以及物体摆放分布。若某个范围内大部分尝试都被拒绝，要么范围不合理，需要缩小；要么暴露了轨迹迁移的弱点，需要修复迁移方法。若通过筛选的位置集中在某个角落，说明实际多样性低于配置所声称的水平。**绝不通过放宽成功条件或物理阈值来提高接受率。**
5. **生成**所需数量的任务序列。仿真以确定性方式并行运行。配置不变时，恢复运行保留已接受的任务序列。
6. **建立真实感基线**，见 §5.4，并完成独立审查。
7. **渲染**通过筛选的任务序列，输出头部和腕部相机图像及标签掩码。
8. 按机器人数据格式**导出**，并**审计**数据集。

### 5.2 随机化维度

每个任务序列由**冻结基础场景加上包含绝对值的变体覆盖层**构成。仿真和渲染使用同一任务序列，并可通过“基础场景 + 变体”复现。

| 维度 | 随机化内容 | 范围选择依据 |
|---|---|---|
| 空间布局 | 物体／目标初始位姿，包括平面平移和偏航角 | 支撑面、头部相机可见性、机器人可达性（在位置网格上求解 IK）；偏航范围还受腕部限位约束 |
| 物理 | 质量、摩擦、执行器增益、控制延迟 | 围绕场景先验变化，范围与已声明的不确定性相符 |
| 灯光 | 强度、色温、位置、尺寸、补光 | 围绕重建的灯光配置变化 |
| 材质 | 色相／饱和度偏移、大表面纹理替换 | 仅在任务允许时变化，不能把任务物体改色成另一种物体 |
| 相机安装 | 毫米级、不到一度的小偏移 | 对已标定安装位姿进行小扰动 |
| 传感器 | 曝光、白平衡、轻微模糊和噪声 | 小幅变化，并固定随机种子 |
| 轨迹 | 速度、途经点偏移、抓取／放置偏移 | 只有单维度消融实验表明抓取可以承受时，才加入抓取偏移 |

### 5.3 轨迹迁移与验收

**按阶段进行以物体为中心的重新锚定。** 将示范中的掌心路径映射到新的物体和目标位姿：

- 机械臂开始运动前保持不变；
- 在预抓取阶段结束前，通过最小加加速度插值与球面线性插值（slerp）平滑过渡到物体坐标系；
- 到抬起阶段前，保持相对物体坐标系的刚性关系；
- 在放置前过渡到目标坐标系，之后保持相对目标的关系；对于容器，仅跟随目标位置。

手指保留示范目标。机械臂关节通过带限位和平滑处理的 IK 求解，再应用变体的时间变换。最终结果由物理仿真决定。

**逐任务序列验收：**

- 满足任务成功判定条件；
- 各类接触的穿透量均在阈值内；
- 机械臂和手指执行器饱和程度在阈值内，抓握期间允许手指达到力／力矩上限；
- 满足关节限位、IK 误差和关节速度要求；
- 末尾保留静置时间，让物体稳定下来；
- 降低数值精度后重新执行，任务仍然成功。

被拒绝的任务序列记录失败阶段和原因，绝不修补成成功样本：不得逐条放宽成功条件，也不得在阶段之间瞬移物体。

### 5.4 真实感基线门禁

先对标称任务序列进行原始渲染，修复材质和灯光，再分别拟合各相机的成像模型。将处理并编码后的结果与真实视频比较，通过独立审查后，才能开始批量渲染。

- 相机成像模型包含色调、暗角、柔化、噪声和码率，根据各帧共有的静态像素拟合，并使用留出数据验证。模型**按相机分别拟合**：腕部相机绝不继承头部相机的处理参数。
- 标签渲染不应用图像处理和运动模糊。
- 基线通过指纹固定版本，覆盖场景、资产、代码、成像模型、渲染设置、变体和运动。
- 若当前指纹及所有相机没有通过独立审查，**批量渲染将拒绝启动**。恢复运行和导出也拒绝使用过期渲染。
- 更多采样、路径追踪渲染器或一次成功的标定运行，本身都不能作为真实感达标的证据。

### 5.5 导出与审计

**导出：** 每个任务序列的头部和腕部视频、状态／动作表、任务指令及来源记录。

- **状态**来自实际执行结果，**动作**来自控制目标。绝不将控制指令作为状态导出。
- 仿真器无法提供的量，如电机电流、力和力矩，保持为零并列为不可用，不得编造。

**审计：**

- 格式检查；
- **重新执行导出的动作**仍然成功；
- 动作／状态映射与正向运动学一致；
- 多样性符合配置声明；
- 图像曝光合理，目标物体可见；
- 导出状态与画面一致，通过标签 IoU 检查。

## 6. 各步骤的验收

| 步骤 | 主要硬性门禁 |
|---|---|
| 场景 | 每个值有来源；遵守输入限制；相机和尺度经过交叉验证；所有帧上的对齐；物体结构正确；补全部分已标记；场景和材质干净；使用一套物理合理的灯光；物理静置稳定；源视角外观达标 |
| 轨迹 | 机器人和上游产物未改变，或存在已声明修订；轨迹为刚性变换；至少两种线索支持真实尺度；留出帧配准验证；机器人手部尺度；接触时间；真实物理；可行性；任务成功；运动忠实度；渲染；交付物 |
| 数据生成 | 配置有依据；每个任务序列有效且成功；动作重放；标称结果忠实度；多样性；渲染；真实感；标签一致性；格式 |

每项门禁的状态为通过、失败或未知。未知会阻止验收通过，软评分不能抵消任何硬性门禁失败。

## 7. 架构摘要

- **由 Agent 构建。** 编码 Agent（Builder）负责运行各步骤，选择方法，通过轻量工具服务调用感知、拟合、仿真、渲染、指标和导出等通用能力，并自行编写场景专用代码，包括参数化形状生成器、去光照、抓取修正和轨迹迁移调整。
- **独立评估。** Builder 冻结候选结果。独立 Evaluator Agent 使用相同工具重新测量，逐条评判验收标准，并指出每项失败应由哪个步骤负责。Builder 修复对应步骤后，重新冻结候选。
- **唯一事实源。** 统一的场景描述包含来源、机器人、三种运动和变体覆盖层，并由此编译得到物理仿真、渲染和 Isaac 导出产物。
- **可靠执行与完整记录。** 工具以独立于调用方、环境隔离且有内存上限的任务运行，每次执行都写入凭证。会话记录完整 Agent 轨迹和 token 使用量，并依据 Builder 的工作日志恢复运行。
